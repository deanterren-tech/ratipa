## 3. Часть 2 — Анализ бизнес-логики учёта разрешений

### 3.1 Статусы бланков и их реальный смысл

| Статус | Этикетка | Количество в системе | Реальный смысл |
|--------|----------|---------------------|----------------|
| `office` | В офисе | Много | Бланк на руках в офисе, готов к выдаче |
| `available` | В наличии | Мало | **Дублирует `office`** (используется как начальный при создании) |
| `hand` | В рейсе / на руках | Среднее | Выдан водителю, в рейсе |
| `office_return` | Сдан в офис / Использован | Среднее | Водитель вернул использованный бланк в офис |
| `used` | Сдан в ТИ | Растёт | Офис передал бланк в транспортную инспекцию |
| `expired` | Аннулирован | Мало | Бланк признан недействительным |

**Проблемы статусов:**
1. **`available` и `office` — синонимы**. В коде они оба считаются как "в офисе" (строка 812-814: `office: raw.filter(i => i.status === "office" || i.status === "available")`)
2. **Нет валидации переходов** — можно перевести `expired` → `hand` (обратно в рейс). Любой статус → любой другой
3. **Нет аудита кто и когда изменил** — лог пишется отдельно через `logAction`, но не хранится в записи бланка
4. **Статус не привязан к дате** — нет `statusChangedAt`

### 3.2 Квоты: как работает расчёт

**Формула квоты:**
```
calculatedLimit = min(
    driversCount * (percent / 100),   // процентная квота
    quarterLimit                       // квартальная квота (если > 0)
)
```

**Расчёт "в работе":**
```
Получено (received)  = кол-во бланков типа, не used, не expired, не isCopy
Использовано (used)  = из них со статусом office_return
В работе (inWork)    = received - used (т.е. office + hand)
Остаток (remaining)  = max(0, limit - inWork)
```

**Проблемы квот:**
1. **Терминологическая путаница**: в квоте `used` (использовано) = статус `office_return`. А статус `used` означает "Сдан в ТИ". Одно слово — два значения.
2. **`quotaGlobalDriversCount`** — просто число, не синхронизировано с реальным количеством водителей
3. **Квартальный лимит не имеет даты** — нет привязки к кварталу (Q1, Q2...), просто число
4. **Квота не проверяется при выдаче** — можно выдать бланк, даже если `remaining = 0`
5. **Копии (isCopy) не учитываются** в квоте, хотя копия использует оригинальный бланк
6. **Нет истории квот** — изменения `quotaTypesPercents` и `quarterLimits` не логируются

### 3.3 Связь с водителями/автомобилями

**Текущая схема:**
- Поле `car` в записи бланка — строка (номер авто или название локации)
- Привязка дозвола к машине — через поле `car` (строка, свободный ввод)
- CouplingPicker ищет и по машинам, и по локациям (mode="combined")
- Нет связи "водитель — бланк" напрямую

**Проблемы:**
1. **car — это и авто, и локация**. Когда статус `office`, car = "Минск офис". Это не машина.
2. **Нет привязки к водителю** — невозможно сказать, у какого водителя бланк
3. **При смене статуса `hand` → `office_return` — car не очищается** (кроме Documents.tsx)
4. **`assignedVehicle`** — поле упоминается в DozvolaLocations (строка 400, 518, 827, 953), но не используется в DozvolaRegistryList — ещё один алиас

### 3.4 Китайские копии (CHN 2, CHN 3)

**Специфическая логика:**
- Для CHN 2/3 существует понятие "копия" (isCopy)
- После сдачи копии есть 30 дней на сдачу оригинала
- Трекинг: `copySubmittedAt`, `isCopy`, `chinaCopySubmitted`
- 30-дневный счётчик на виджетах и в карточке строки

**Проблемы:**
1. **Три поля для одной сущности**: `isCopy`, `copySubmittedAt`, `chinaCopySubmitted` — размазано
2. **30 дней хардкод** в трёх местах (DozvolaWidgets строка 496, DozvolaRow строка 272)
3. **`chinaCopySubmitted`** — отдельный флаг, который не отображается в основной таблице реестра
4. **Копия ≠ оригинал**: бланк учитывается как "полученный" в квоте даже если сдана только копия

### 3.5 Логирование (dozvolsHistoryV4)

**Структура записи:**
```
{ time, logist, doc, action, meta }
```

**Проблемы:**
1. **`time` — строка (ru-RU locale)**, а не ISO timestamp — нельзя сортировать по дате
2. **`logist` — localStorage.getItem('ratipa_auth_user')** — не синхронизировано с сессией
3. **Нет type/категории** — нельзя фильтровать по типу действия
4. **Дублирование**: документы пишут и в `dozvolsHistoryV4`, и в `dozvolsDocumentsHistoryV1`
5. **Удаление записей** в `DozvolaHistory.tsx` — лог должен быть immutable

### 3.6 Документооборот

**Три типа документов:**
1. **Заявление на получение разрешений** — на основе заявок планерки
2. **Реестр возврата разрешений** — на основе статуса `office_return`
3. **Заявление по китайским копиям** — на основе CHN 2/3 с isCopy

**Проблемы:**
1. **Дата заявления (applicationDate) — одна на все три типа**, хотя это независимые события
2. **`lastAssembledStatementPermitsV1`** — хранит предыдущее заявление, но только для возврата. Для заявления на получение и китайских копий такого нет
3. **При списании (office_return → used) очищается car** (Documents строка 402), но это не делается в RegistryList при inline-смене статуса на `used`
